Multi-Token Prediction (MTP)

Standard LLMs predict one token at a time. MTP adds D sequential prediction heads so the model learns to anticipate further ahead — improving representations during training and enabling speculative decoding at inference for free throughput.

What each MTP module contains:

• Its own embedding layer (shared weights with main model)
• Its own lightweight transformer block
• Its own output projection / LM head

Each MTP module takes the main model's hidden state h_t and the embedded token at offset t+k, then outputs a distribution over vocabulary for position t+k+1.

Why sequential, not parallel?
Module k feeds into module k+1. Each module can condition on the previous module's output — so head 2 knows what head 1 predicted before it predicts t+3. This respects the autoregressive dependency chain even across future positions.
Training objective:
L_total = L_main + λ · (L_mtp1 + L_mtp2 + ... + L_mtpD)

λ starts at 0.3 and drops to 0.1 near the end of the LR schedule. Each L_mtp feeds gradients through the MTP module AND back into the shared trunk, enriching the main model's hidden representations.

Inference: MTP Heads → Speculative Decoding

At inference the MTP modules aren't thrown away — they become draft generators. The main model verifies all drafts in one forward pass. If they match, you get multiple tokens for the cost of one.

Why This Doesn't Change the Output Distribution
The main model acts as a verifier. For each draft token, it checks: "would I have generated this token with ≥ the draft probability?" If yes → accept. If no → reject and sample from the corrected distribution. The math guarantees the joint distribution of accepted tokens is identical to what the main model would produce without drafts — you get throughput for free, with no quality tradeoff.

Summary — Two Benefits, One Mechanism
During Training

• D extra cross-entropy losses per position
• Gradients flow back through MTP heads into the main trunk
• Forces hidden states h_t to encode information about future context
• Richer, more predictive representations → better downstream quality
During Inference

• MTP heads draft D tokens ahead cheaply
• Main model verifies all D drafts in one pass
• Accepted tokens are free — same quality, higher throughput
• No architectural change needed at inference time
