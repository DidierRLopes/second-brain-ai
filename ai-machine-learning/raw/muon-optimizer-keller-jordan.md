# Muon: An optimizer for hidden layers in neural networks

**Source:** Keller Jordan's blog
**URL:** https://kellerjordan.github.io/posts/muon/
**Author:** Keller Jordan
**Date:** December 8, 2024
**Fetched:** 2026-05-25

Muon (**M**oment**U**m **O**rthogonalized by **N**ewton-Schulz) is an optimizer for 2D parameters of neural network hidden layers. It currently holds training speed records for both NanoGPT and CIFAR-10 speedrunning.

## Definition

Muon takes the updates generated by SGD-momentum and applies a Newton-Schulz (NS) iteration as a post-processing step before applying them to the parameters. The NS iteration approximately *orthogonalizes* the update matrix — it replaces the update with the nearest semi-orthogonal matrix, equivalent to replacing the update by `U V^T` where `U S V^T` is its SVD.

Scalar and vector parameters as well as input and output layers should be optimized with a standard method (AdamW). Muon can be used for 4D convolutional parameters by flattening their last three dimensions.

### Newton-Schulz iteration (PyTorch)

```python
def newtonschulz5(G, steps=5, eps=1e-7):
    assert G.ndim == 2
    a, b, c = (3.4445, -4.7750, 2.0315)
    X = G.bfloat16()
    X /= (X.norm() + eps)
    if G.size(0) > G.size(1):
        X = X.T
    for _ in range(steps):
        A = X @ X.T
        B = b * A + c * A @ A
        X = a * X + B @ X
    if G.size(0) > G.size(1):
        X = X.T
    return X
```

## Results

- Improved the CIFAR-10 94% training-time record from 3.3 to 2.6 A100-seconds.
- Improved the NanoGPT speedrunning record (3.28 val loss on FineWeb) by 1.35x.
- Continued speed improvements scaling to 774M and 1.5B parameters.
- Trained a 1.5B transformer to GPT-2 XL HellaSwag level in 10 8×H100-hours; AdamW takes 13.3 hours.

## Why orthogonalize?

Empirically, the updates produced by SGD-momentum and Adam for 2D parameters in transformers typically have very high condition number — they are nearly low-rank, with updates for all neurons dominated by a few directions. Orthogonalization effectively increases the scale of "rare directions" which have small magnitude in the raw update but are important for learning.

A theoretical motivation comes from Bernstein & Newhouse (2024)'s analysis of Shampoo.

## Why Newton-Schulz over SVD/Coupled Newton?

- **SVD**: easy to understand, far too slow.
- **Coupled Newton iteration** (used in Shampoo for inverse-fourth roots): must run in float32 to avoid numerical instability, which makes it slow on modern GPUs.
- **Newton-Schulz iteration**: can be stably run in bfloat16.

## Math of NS iteration

For SVD `G = U S V^T`, one step of NS with coefficients `(a, b, c)` yields:

```
G' = aG + b(GG^T)G + c(GG^T)^2 G
   = U(aS + bS^3 + cS^5)V^T
```

If we define `φ(x) = ax + bx^3 + cx^5`, then N steps of NS gives `U φ^N(S) V^T`. To converge to `Ortho(G) = U V^T`:
1. Normalize initial entries of S to `[0, 1]` (replace G by G/||G||_F before starting; benign since `Ortho(cG) = Ortho(G)`).
2. Select coefficients so `φ^N(x) → 1` as N → ∞ for all `x ∈ [0, 1]`.

### Tuning the coefficients

The baseline `(a, b, c) = (2, -1.5, 0.5)` works. To reduce NS steps:

1. Maximize `a` (controls convergence rate for small initial singular values, since `φ'(0) = a`).
2. Empirically, `ε` (tolerance around 1) can be as high as 0.3 without harming loss. Goal: maximize `a` subject to `lim φ^N(x) ∈ [0.7, 1.3]`.

Ad-hoc gradient-based optimization yields `(3.4445, -4.7750, 2.0315)`. With these, 5 NS steps suffice for transformers and small convnets. Third- and seventh-order polynomials don't improve wallclock further.

## Runtime analysis

Before NS, Muon = SGD-momentum (same memory).

For each `n × m` matrix parameter (with `m ≤ n`), each NS step needs `2(2nm^2 + m^3)` matmul FLOPs, at most `6nm^2` for square. Extra FLOPs vs SGD: at most `6Tnm^2` with `T` NS iterations (typically `T=5`).

Baseline FLOPs for a step on a linear layer: `6nmB` (B = inputs through the layer).

**FLOP overhead of Muon: at most `Tm/B`**, where `m` = model dim, `B` = batch tokens, `T` = NS steps.

- NanoGPT speedrun (`m=768`, `B=524288`): `5 × 768 / 524288 = 0.7%`.
- Llama 405B (`m=16384`, `B=16M`): `5 × 16384 / 16M = 0.5%`.

For typical LM training scenarios, Muon's FLOP overhead is below 1%.

## Relationship to prior optimizers

### Shampoo

Shampoo's update, when preconditioner accumulation is removed (per Bernstein & Newhouse 2024):

```
W_{t+1} = W_t - η (G G^T)^{-1/4} G (G^T G)^{-1/4}
        = W_t - η U V^T
```

The orthogonalized gradient. If we then add momentum *before* orthogonalization, we recover Muon — with lower wallclock/FLOP overhead since NS replaces inverse-fourth roots. Muon (no momentum) can be interpreted as "instantaneous" or "accumulation-free" Shampoo.

### Orthogonal-SGDM (Tuddenham et al., 2022)

Optimizes by orthogonalizing the gradient via SVD, then applying momentum to the result. Muon differs: momentum *before* orthogonalization (better empirically), NS iteration instead of SVD.

### Stochastic spectral descent / RMSspectral (Carlson et al., 2015–2016)

Earlier orthogonalization-based optimizers using SVD (or randomized SVD) without momentum.

## Empirical considerations

- Muon only applies to 2D parameters (and conv filters via flattening). Scalar/vector parameters, plus **input and output layers** (embeddings, classifier head), should use AdamW. Embedding follows from modular norm theory (Large et al. 2024); output is empirically driven.
- Nesterov-style momentum works better than normal SGD-momentum (default in public impl).
- Muon works better when applied to transformer Q, K, V parameters separately rather than jointly as a single QKV linear layer.
