# Practical Fine-Tuning

This article collects practical guidance for fine-tuning LLMs, drawing on recommendations from Sebastian Raschka, Hugging Face, and other practitioners, with a bias toward choices that matter in small-team fine-tuning: data quality, chat formatting, adapter scope, evaluation, and when multi-turn agents need DAgger-style on-policy supervision instead of plain SFT.

## When to Fine-Tune

Fine-tuning makes sense when: you need consistent behavior on a specific task, your domain has specialized vocabulary or formats, you want to distill capabilities from a larger model, or prompt engineering alone doesn't achieve the required quality. For many tasks, few-shot prompting or RAG is sufficient without fine-tuning.

## Supervised Fine-Tuning (SFT)

SFT is the starting point — training on (instruction, response) pairs. Key decisions:

**Data quality over quantity:** A few thousand high-quality examples often outperform millions of noisy ones. Clean, diverse, and representative data matters most.

**Chat template formatting:** Use the model's expected chat format (e.g., ChatML, Llama format). Inconsistent formatting degrades quality.

**Training hyperparameters for LoRA:** Start with rank r=8-16, learning rate 1e-4 to 3e-4, batch size 4-8 with gradient accumulation. Train for 1-3 epochs — LoRA overfits faster than full fine-tuning.

**Which layers to adapt:** Applying LoRA to all linear layers (Q, K, V, O projections + MLP) generally outperforms targeting only attention weights, at modest additional cost.

## Common Pitfalls

**Catastrophic forgetting:** Fine-tuning too aggressively can damage general capabilities. Use lower learning rates and fewer epochs. LoRA naturally mitigates this since most weights are frozen.

**Evaluation mismatch:** Training loss doesn't capture quality well. Use task-specific benchmarks and human evaluation. Perplexity alone can be misleading.

**Data contamination:** Ensure your test set doesn't overlap with training data. This is especially important with synthetic data from larger models.

## Multi-Turn Agent Training: DAgger vs SFT vs RL

For long-horizon agentic tasks (e.g., software engineering agents, web browsing, research), the choice of post-training algorithm dramatically impacts both efficiency and final performance.

**SFT on expert trajectories** provides dense supervision but suffers **covariate shift**: the model trains only on states visited by the teacher, so early errors during deployment diverge the trajectory distribution. Imitation error scales quadratically with horizon.

**RL with verifiable rewards (RLVR)** addresses distribution mismatch by training on student-only rollouts, but suffers **sparse credit assignment** (single outcome reward per trajectory) and computational cost from group sampling. Advantage estimates collapse when few trajectories are correct.

**DAgger** ([Revisiting DAgger in the Era of LLM-Agents (2605.12913)](../../papers/05-learning/fine-tuning/Revisiting DAgger in the Era of LLM-Agents - 2605.12913.pdf)) for LM agents revisits the classical imitation-learning algorithm, adapting it for multi-turn settings via **teacher-interleaved rollouts**: each trajectory is generated by a stochastic mixture μ_i = β_i π_e + (1 - β_i)π_θ, where β_i decays toward 0. For each visited state, the student or teacher acts based on a scheduler, but the teacher always provides a label for SFT. This gives:
- **On-policy data** (student visits deployment-time states)
- **Dense supervision** (every token labeled by the teacher)
- **Cold-start robustness** (teacher takeovers recover from early failures)
- **Computational efficiency** (no group sampling or value models needed)

Empirically on SWE-Bench Verified: DAgger-trained Qwen3-4B reaches 27.3%, outperforming published 8B agents (+8.3 points vs SkyRL-Agent-8B-v0), while Qwen3-8B reaches 29.8%, approaching 32B-scale agents (within 5 points of the strongest published 32B systems). The 2× compute advantage over SFT+RL persists even after accounting for the cost of collecting expert trajectories.

## Tools

- **Hugging Face SFTTrainer:** High-level API for supervised fine-tuning with PEFT integration
- **Hugging Face PEFT library:** Implements LoRA, QLoRA, prefix tuning, and other adapters
- **bitsandbytes:** Enables 4-bit and 8-bit loading for QLoRA training
- **Axolotl:** Full-featured fine-tuning framework with many preset configurations
- **Unsloth:** Optimized LoRA training with 2× speed improvement
- **TRL (Transformer Reinforcement Learning):** Implements GRPO, PPO, DPO, and other alignment algorithms
- **verl:** Large-scale RL training framework with DAPO, GRPO, and group-based reward integration
